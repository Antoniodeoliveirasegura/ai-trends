Models & Releases

Z.ai's GLM-5.4 is the first flagship model built as a "loop transformer." Instead of adding layers, it runs a 28-layer block twice inside a roughly 750B base. Z.ai claims performance comparable to 2–3T-parameter models and says it validated the design at 1B, 4B, 30B and 750B. Z.ai published no benchmark scores at launch. Its internal evaluation shows 51% wins against GLM-5.3, and independent KingBench 4 ranks it 7th of 19. There is no API and no open weights yet; access is limited to GLM Coding Plan subscribers. HN is excited about the architecture and wants the numbers.

Tooling

Shirudo: OpenAI and Cisco open-source a Linux runtime in which agents write eBPF "shields" that block exploits on unpatched, running servers. The pitch is to close the gap between disclosure and patch rollout without restarting services. In Cisco's demo, a shield written with Codex blocked a Java4Shell exploit against Elasticsearch. It is BSD-2 licensed and descends from Tetragon. The project is pre-release, and production use needs a patched kernel and TPM 2.0. Agent-written code running in the production kernel path is the part to watch.

Research

DeepMind and Google Quantum AI: Gemini agent teams find quantum programs that a Lean 4 prover checks for both correctness and resource cost. The teams shared a wiki of verified Lean files and dead ends, and met every four hours in scheduled "conferences." The headline result is a roughly 290× resource reduction for computing arcsine, with about 11× and 8× gains on two chemistry and physics simulations. The library is public. These are analytic estimates, and nothing ran on quantum hardware.

CoEvoBench (Alibaba): can an LLM improve both a model and its agent harness, and then keep improving? Frontier models act as the "researcher." Each gets a 9B base model, a harness and 24 hours. The best closed more than 80% of the gap to an instruction-tuned reference, but the authors find that models make one strong improvement and then can't use feedback from the improved system to make the next one. That is a measured result on recursive self-improvement, a question argued mostly in rhetoric all month.

Quiet but worth watching

"Who Grades the Agent?" SplitBench puts privilege separation into coding-agent benchmarks. Today's coding benchmarks grade by running the agent's own code, so the thing being measured controls the measuring tool. SplitBench moves the expected answers to a trusted grader, so an agent that controls the whole test environment still can't fake a pass. A secondary write-up reports 98.7% agreement with native graders. As labs report bigger agent scores every week, this is the kind of plumbing that decides which scores to believe. arXiv 2611.27860 · DEV write-up
